# Security boundaries

Latest Supabase changelog and Auth/SSR/RLS/Storage documentation checked before implementation, including explicit Data API grants and PostgreSQL changes. Details and URLs in SUPABASE_REVIEW.md.

- RLS required on every exposed table; `TO authenticated` alone is never the policy.
- Private helper checks `auth.uid()` and active workspace membership. Fixed search path, qualified names, no supplied target user, execution revoked from PUBLIC/anon. Avoids membership-policy recursion, not a generic authorization bypass.
- Private signup trigger creates constant owner role for the newly inserted auth.users identity; metadata used only for display. No remotely callable privileged bootstrap.
- Business updates cannot change workspace. Composite FK prevents cross-tenant relationships.
- User credential for all app CRUD/signed upload; service key is never in client or iOS. Public share routes use a server-only 256-bit gateway capability plus the ordinary publishable credential; the database stores only the capability hash and returns a minimal explicit scope.
- Signed private media URLs expire after 5 minutes. Signed uploads require registered media row and private bucket RLS. Completion verifies object name and byte size.
- Same-origin checks on mutation APIs. PKCE SSR cookies; getUser on protected pages/API for current authenticated identity; proxy refresh. No MaxQI passwords or cookies.
- 256-bit random share tokens, SHA-256 stored, expiry mandatory, read-only, revoke supported. General business-table grants and direct anon/auth execution of the old resolver/status RPCs are absent. Invalid/revoked/expired tokens return only fixed states. Public projections omit internal notes and arbitrary metadata. No-referrer and no-store, share page noindex. Postgres atomically enforces distributed caller/token budgets for every Vercel instance; the process-local limiter is early defense only.
- Local queue contains private text/photos; physically accessible browser device can access them. Scoped by logged-in user and workspace and not exposed across in-app accounts, persists on logout to avoid losing unsent work. Device cleanup/encryption policy is future work.
- `.env*`, source exports, reports and storage-copy credentials excluded from Git. Independent backend guard rejects MaxQI and PROS projects.

Validation: real PostgreSQL 17 tests cover bootstrap, different users, viewer/suspended memberships, anonymous access, role escalation, cross-workspace FK, and storage writes. More tests include workspace immutability and share scope. Hosted owner/nonmember assertions and advisors have also been reviewed. Physical iOS permission tests remain pending; unsigned macOS CI builds pass.

## LandOS spatial security verification

Additive drawing RPC uses SECURITY INVOKER, fixed search_path, explicit active editor membership and all original Workspace RLS/FKs. PUBLIC/anon execution revoked. Two-user DB tests now cover normalized feature reads and cross-tenant RPC calls. Editor deletion applies only to their Workspace Features; layer delete remains manager-only. API rejects invalid coordinates/unclosed rings and duplicate identities. Reference catalog read policy is intentionally global for authenticated users; it contains public government-service metadata, not Workspace data. Preference rows require auth.uid plus active membership; catalog/entitlement client writes denied. Workspace cookie selection validates active membership.

Hosted security advisor currently reports existing leaked-password protection disabled; enabling depends on supported Supabase Auth plan/configuration. See https://supabase.com/docs/guides/auth/password-security. No missing-RLS warning. Real device/private Storage workflow remains separate from compile-only acceptance.

Saved View links freeze parcel/layer IDs and Feature UUIDs at creation. Later features added to a shared layer are excluded from that View link. Private feature properties and geometry extra members are stripped by database projection. Raw share tokens and caller addresses become one-way hashes before database budget storage. Public Web pages call the LandOS server, which validates token format, applies early and distributed budgets, and invokes the protected gateway. The old resolver/status functions deny anon/auth execution. The gateway accepts no Workspace/table/query argument, has a fixed search path, checks the server capability, enforces expiry/revocation and returns a fixed envelope. Database, browser and production tests verify scope, future-feature exclusion, note stripping, invalid/malformed tokens, revoke, expiry and 429. Public tile requests send origin-only Referer without token; other external links keep no-referrer.

Hosted advisor after gateway cutover reports one intentional WARN because anon can execute SECURITY DEFINER `landos_share_gateway`, plus existing leaked-password protection disabled. The gateway rejects calls without the server-only 256-bit capability before resolution and budgeted public read; authenticated execution is revoked. Direct old resolver/status execution is revoked for both anon and authenticated roles. Reviewed with database, anonymous-browser and hosted synthetic acceptance. See https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable. Do not report this advisor as warning-free; no missing-RLS/table-grant finding.

## Alpha 2 public sharing

Creating a Saved View share first performs a no-write scope preview. Counts explicitly include selected layers' current features outside the viewport; private observations/photos/notes are excluded. The UI supplies a scope hash on create, so changed scope requires another review. Current feature IDs are frozen, total at most 5,000. Share managers list metadata without token/hash disclosure. The database stores token hashes; copy URLs are retained only in scoped device IndexedDB (browser bearer capabilities), never committed or available to another account/Workspace. Revocation/expiry are checked on every public projection; no CDN/application projection cache is introduced.

`landos_share_status` remains a narrow internal function with empty search path and strict 43-character random token format. It returns only expired/active/unavailable; revoked and unknown are indistinguishable. It exposes no workspace/resource identifiers and no longer grants anon/auth execution. Expired API requests return 410 with only a fixed message.

Public Web/API paths have bounded early process budgets plus atomic Postgres budgets of 120 caller/minute and 60 token/minute; 429 includes Retry-After and no-store. Caller IPs are HMAC-hashed by the server and raw tokens are never stored in rate buckets. Concurrent production acceptance demonstrated shared enforcement. Vercel WAF remains optional defense in depth because project Firewall configuration currently returns HTTP404 `Seawall Config not found`; see SHARE_PERIMETER.md. No user or server credential is committed.

Hosted advisor review 2026-10-08: the old resolver/status warnings are removed. One intentional anon SECURITY DEFINER warning covers the capability-protected, distributed-budget gateway; leaked-password protection remains disabled. No authenticated gateway or missing-RLS finding. Review [public capability function guidance](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable) and [password protection setup](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). This project is not described as warning-free.

Alpha 3 Planning reads authorize the saved Property via current Workspace membership/RLS before external geometry submission. The provider contract uses only fixed reviewed URLs and allowlisted attributes; geometry never enters URL/access logging. No public Planning endpoint or privileged CRUD is introduced. Fresh changelog/RLS docs checked 2026-10-07; catalog review adds only server-owned metadata, with existing read-only authenticated/RLS grants. Hosted advisor findings remain the two narrow token capability functions and leaked-password protection; no new missing-RLS finding.

Alpha 3 sync tables are RLS-enabled, member SELECT only, with no client event writes. The non-exposed trigger serializes revisions transactionally and records parent invalidation for media deletion; the public cursor RPC is SECURITY INVOKER, authenticated membership checked and anon execution denied. Hosted rollback owner/nonmember/anon checks passed. [SHARE_PERIMETER.md](SHARE_PERIMETER.md) records the completed distributed gateway cutover and the separate optional Vercel Firewall 404 blocker.

Client operational diagnostics accept only a strict fixed event enum, current authenticated Workspace membership and same-origin POST, with bounded body/per-account process budgets. Arbitrary error text, URLs, geometry/IDs and extra fields are rejected; only fixed category/time/public deployment release are emitted. Sharing/RPC diagnostics never log tokens/caller identifiers. Server instrumentation logs only fixed route patterns/types and release/time.
