# Security boundaries

Latest Supabase changelog and Auth/SSR/RLS/Storage documentation checked before implementation, including explicit Data API grants and PostgreSQL changes. Details and URLs in SUPABASE_REVIEW.md.

- RLS required on every exposed table; `TO authenticated` alone is never the policy.
- Private helper checks `auth.uid()` and active workspace membership. Fixed search path, qualified names, no supplied target user, execution revoked from PUBLIC/anon. Avoids membership-policy recursion, not a generic authorization bypass.
- Private signup trigger creates constant owner role for the newly inserted auth.users identity; metadata used only for display. No remotely callable privileged bootstrap.
- Business updates cannot change workspace. Composite FK prevents cross-tenant relationships.
- User credential for all app CRUD/signed upload; service key is never in client or iOS. Token-only database resolver returns a minimal explicit scope; no runtime service key needed.
- Signed private media URLs expire after 5 minutes. Signed uploads require registered media row and private bucket RLS. Completion verifies object name and byte size.
- Same-origin checks on mutation APIs. PKCE SSR cookies; getUser on protected pages/API for current authenticated identity; proxy refresh. No MaxQI passwords or cookies.
- 256-bit random share tokens, SHA-256 stored, expiry mandatory, read-only, revoke supported. Anonymous database grants absent. Invalid/revoked/expired tokens return unavailable. Public projections omit internal notes and arbitrary metadata. No-referrer and no-store, share page noindex. Future public launch requires shared-endpoint rate limiting at deployment perimeter.
- Local queue contains private text/photos; physically accessible browser device can access them. Scoped by logged-in user and workspace and not exposed across in-app accounts, persists on logout to avoid losing unsent work. Device cleanup/encryption policy is future work.
- `.env*`, source exports, reports and storage-copy credentials excluded from Git. Independent backend guard rejects MaxQI and PROS projects.

Validation: real PostgreSQL 17 tests cover bootstrap, different users, viewer/suspended memberships, anonymous access, role escalation, cross-workspace FK, and storage writes. More tests include workspace immutability and share scope. Hosted owner/nonmember assertions and advisors have also been reviewed. Physical iOS permission tests remain pending; unsigned macOS CI builds pass.

## LandOS spatial security verification

Additive drawing RPC uses SECURITY INVOKER, fixed search_path, explicit active editor membership and all original Workspace RLS/FKs. PUBLIC/anon execution revoked. Two-user DB tests now cover normalized feature reads and cross-tenant RPC calls. Editor deletion applies only to their Workspace Features; layer delete remains manager-only. API rejects invalid coordinates/unclosed rings and duplicate identities. Reference catalog read policy is intentionally global for authenticated users; it contains public government-service metadata, not Workspace data. Preference rows require auth.uid plus active membership; catalog/entitlement client writes denied. Workspace cookie selection validates active membership.

Hosted security advisor currently reports existing leaked-password protection disabled; enabling depends on supported Supabase Auth plan/configuration. See https://supabase.com/docs/guides/auth/password-security. No missing-RLS warning. Real device/private Storage workflow remains separate from compile-only acceptance.

Saved View links freeze parcel/layer IDs and Feature UUIDs at creation. Later features added to a shared layer are excluded from that View link. Private feature properties and geometry extra members are stripped by database projection. Raw share token is hashed inside PostgreSQL SHA-256; knowing stored 64-character hash cannot call the 43-character-token resolver. Resolver is the sole public SECURITY DEFINER read path, accepts no Workspace/table/query argument, fixed search_path, expiry/revocation enforced, no general anon business-table grants. Database tests and anonymous browser tests verify scope, future-feature exclusion, note stripping, invalid/hash token and revoke. Public viewer uses only publishable credential plus this RPC, never service role. Public tile requests send origin-only Referer without token; other external links keep no-referrer. Perimeter throttling remains required before broad public launch.

Hosted advisor after public projection reports two intentional WARNs (anon/authenticated can execute SECURITY DEFINER resolve_landos_share) plus existing leaked-password protection disabled. The executable function is deliberately the capability-token public read path required for passwordless sharing, not a general Workspace RLS bypass: raw token only, hash internally, fixed path, expiry/revoke, immutable scope and minimal projection. Reviewed with database/anonymous-browser scope tests. See https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable and lint 0029. Do not report this advisor as warning-free; no missing-RLS/table-grant finding.

## Alpha 2 public sharing

Creating a Saved View share first performs a no-write scope preview. Counts explicitly include selected layers' current features outside the viewport; private observations/photos/notes are excluded. The UI supplies a scope hash on create, so changed scope requires another review. Current feature IDs are frozen, total at most 5,000. Share managers list metadata without token/hash disclosure. The database stores token hashes; copy URLs are retained only in scoped device IndexedDB (browser bearer capabilities), never committed or available to another account/Workspace. Revocation/expiry are checked on every public projection; no CDN/application projection cache is introduced.

`landos_share_status` is a separate token-only SECURITY DEFINER function with empty search_path and strict 43-character random token format. It returns only expired/active/unavailable; revoked and unknown are indistinguishable. It exposes no workspace/resource identifiers. This intentional public execute grant may add an advisor warning like the existing narrow share resolver; it is not a general table read grant. Expired API requests return 410 with only a fixed message.

Public Web/API paths have bounded per-process hashed caller/token budgets (120 caller/minute, 60 token/minute); 429 includes Retry-After, no-store. This is an abuse-reduction foundation, not distributed enforcement. Before broad public launch: configure Vercel WAF rate rules for `/share/*` and `/api/published/*`; verify the trusted platform address header, and protect direct Supabase public RPC invocation through a gateway/database-wide budget or move token resolution behind a dedicated server-only role. Vercel-only rules cannot protect a directly accessible Supabase RPC. Complete these infrastructure controls and run multi-instance abuse tests; current scope/RLS/token entropy remain required throughout. No user credential is committed.

Hosted advisor review 2026-10-07: intentional anon/auth SECURITY DEFINER execute warnings each now cover resolve_landos_share and landos_share_status; leaked-password protection remains disabled. No missing-RLS finding. Review [public capability function guidance](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated function guidance](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) and [password protection setup](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). This project is not described as warning-free.

Alpha 3 Planning reads authorize the saved Property via current Workspace membership/RLS before external geometry submission. The provider contract uses only fixed reviewed URLs and allowlisted attributes; geometry never enters URL/access logging. No public Planning endpoint or privileged CRUD is introduced. Fresh changelog/RLS docs checked 2026-10-07; catalog review adds only server-owned metadata, with existing read-only authenticated/RLS grants. Hosted advisor findings remain the two narrow token capability functions and leaked-password protection; no new missing-RLS finding.

Alpha 3 sync tables are RLS-enabled, member SELECT only, with no client event writes. The non-exposed trigger serializes revisions transactionally and records parent invalidation for media deletion; the public cursor RPC is SECURITY INVOKER, authenticated membership checked and anon execution denied. Hosted rollback owner/nonmember/anon checks passed. Public launch perimeter is explicitly unresolved: see [SHARE_PERIMETER.md](SHARE_PERIMETER.md) for reviewed staged rules, actual Vercel HTTP404 responses and the required direct-RPC gateway cutover order. No distributed enforcement is claimed.
