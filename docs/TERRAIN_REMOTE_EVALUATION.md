# Remote terrain evaluation

No remote DEM is enabled for production. The only approved data used in the proof so far is the GA SRTM-derived 1 second DEM v1.0 (CC BY 4.0, EGM96, roughly 30 m source resolution). Its five committed local proof tiles are fixtures, not a nationwide service. Attribution and limitations are in `TERRAIN_GA_POC.md`.

## Direct remote tiles

The [AWS Registry Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) lists global Mapzen/Tilezen data, and the [Tilezen endpoint documentation](https://github.com/tilezen/joerd/blob/master/docs/use-service.md) identifies 256-pixel Terrarium PNGs in the public S3 bucket. A bounded `HEAD` for an Alpine tile returned HTTP 200, 63,122 bytes and `x-amz-meta-x-imagery-sources: srtm/S37E148.tif`. HEAD requests with `Origin: https://landbanker.vercel.app` omitted `Access-Control-Allow-Origin`, but a subsequent GET with that origin returned `Access-Control-Allow-Origin: *`. The GET result supports browser access; an actual browser integration test remains necessary. Tilezen's documentation describes the bucket for EC2 usage, not a guaranteed production browser tile service; commercial multi-user hosting terms, request limits, uptime and budget remain unverified. Its [attribution and source documentation](https://github.com/tilezen/joerd/blob/master/docs/data-sources.md) describes a mosaic, varying source resolutions, older releases and oversampling. It must not be labelled as a uniform GA SRTM/EGM96 dataset without per-tile provenance and datum verification. The terrain controller now permits either 256- or 512-pixel Terrarium tiles, but no source is automatically configured.

[OpenTopography's developer terms](https://opentopography.org/developers) state that integration of their API into commercial software requires an Enterprise key. Public data licensing does not make the free key suitable for this use. No key was requested or embedded.

## GA WCS conversion

Three sequential conversions of the same bounded GA Alpine tile using `scripts/terrain/ga_srtm_tile.py` in this runtime completed in 3.53, 3.41 and 2.04 seconds wall time, producing 542,300-byte PNGs. The maximum child-process RSS observed across those runs was 78,828 KiB. This is a small, warm-environment measurement, not a throughput, cold-start, concurrency or uptime guarantee. There was one WCS request per conversion; cache hit rate was not measured. Extrapolating ten uncached tiles implies ten WCS calls and approximately 20–35 seconds of summed conversion work, though concurrent elapsed time and source load are unknown.

Do not deploy a public on-demand WCS conversion endpoint yet. Open-data reuse rights do not establish acceptable request rates to the WCS. Global rate limiting, request coalescing, denial-of-service protection, cache retention, invalid/no-data handling, metering, and source-operator capacity/permission would need to be established. A Python/GDAL runtime and its memory/cold-start and Vercel plan constraints also require verification. No new infrastructure was provisioned.

## Cost illustration, not a quote

The five GA proof PNGs total 2,426,966 bytes: mean **485,393 bytes** per tile. A hypothetical 1,000 map sessions with ten uncached tiles each would transfer about **4.85 decimal GB** of response bodies; actual requests per session and cache hit rates have not been measured. [Vercel CDN pricing](https://vercel.com/docs/manage-cdn-usage) charges for transfer and requests, and [regional pricing](https://vercel.com/docs/pricing/regional-pricing) lists a regional fast-transfer rate range of $0.15–$0.35/GB for the relevant overage tier. Illustratively, if all 4.85 GB were billable overage at those rates, transfer alone would be about **$0.73–$1.70**, excluding requests, function execution, source access, storage, taxes and any included usage. The active plan, region, cache hit rate and traffic are unknown, so this is not an estimate of the user's actual bill.

The smallest further alternatives are (1) obtain an explicit agreement and CORS-capable commercial-use tile endpoint with documented limits, or (2) establish GA WCS request permission and a tested, bounded caching and conversion service with a spending cap. Costs for either cannot be quoted from the available evidence. Do not enable either or deploy terrain until usage, datums, security, costs and live map/parcel checks are resolved.

## Coverage reporting

The workspace examines MapLibre's rendered terrain coverage index and warns if any rendered terrain tile lacks a DEM sampler or the state is unknown; this is stricter than checking only the map centre. It cannot identify missing values encoded *inside* a loaded raster tile or establish the source's accuracy. Sampling refuses points with no drawn DEM and preserves confirmed zero values. Unknown resolution, datum and accuracy are explicitly labelled; never compare or combine heights across unknown or incompatible datums. The index is a MapLibre 6.16 API and must be revalidated on upgrades.

A separate 1024×768 synthetic-fixture browser test requested 6 distinct DEM tiles initially and 2 additional tiles after one pan. Each synthetic fixture is 51,438 bytes, so these represent approximately 309 kB and 103 kB of fixture response bodies respectively. These counts are from one local test with one map movement; they are not a real-provider traffic model, production cache-hit measurement or reliable estimate for all sessions. The bounded real GA proof tile is much larger and the Tilezen sample is 63,122 bytes, so transfer varies by provider, geography and encoding.
